## Status Vocabulary (strict)

- `MATCH` — used **only** where an actual web-vs-Flutter comparison was
  performed with live evidence (a real account, a real request/response, a
  real on-device screenshot) — not merely because the code looks correct.
- `IMPLEMENTED_NOT_VERIFIED` — Flutter code exists, matches the documented
  web contract on inspection, passes its unit/widget tests, but has not
  itself been exercised against production this pass.
- `PARTIAL` — some but not all of the web screen's content/states are
  reproduced (always with a specific note on what's missing).
- `MISSING` — no Flutter code of any kind, not even a placeholder route.
- `PLACEHOLDER` — a real Flutter route exists but renders `ComingSoonScreen`
  or equivalent.
- `BACKEND_NOT_DEPLOYED` — the endpoint/view exists in the local Django
  checkout (often as an uncommitted diff) but is unreachable on live
  production.
- `WEB_HTML_ONLY` — no JSON API exists on the web side either; Flutter
  reproduces the page via HTML-scraping, matching the web's own
  architecture (not a gap).
- `NOT_APPLICABLE` — infra, a dead/orphaned web-only route, admin, or
  otherwise out of mobile scope by design.
