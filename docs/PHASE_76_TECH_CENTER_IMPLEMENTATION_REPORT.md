# Phase 76 — Tech Center Lesson Discovery & Navigation Implementation Report

See `docs/PHASE_76_TECH_CENTER_NAVIGATION_AUDIT.md` for the full
source-backed investigation this report implements.

## Summary

All 383 previously-unreachable nested Tech Center lesson pages are now
reachable from Flutter, through a new 2-screen-plus-sheet browsing flow
(Departments → Roles → a course-list sheet opening the existing lesson
WebView), built from a generated, verified data manifest rather than
invented structure. The manifest is mechanically extracted from the real
`index.html`'s own already-existing department/role/course markup (the same
page `skill_up_data.dart` itself is transcribed from) and cross-validated
1:1 against the real on-disk files at generation time.

## Screens and routes added

- `TechCenterDepartmentsScreen` — `RoutePaths.techCenterDepartments =
  '/skill-up/tech-center'`.
- `TechCenterRolesScreen` — `RoutePaths.techCenterRoles =
  '/skill-up/tech-center/roles'` (`extra: TechCenterDepartment`).
- `TechCenterRoleSheet` — a bottom sheet (not a route), opened from
  `TechCenterRolesScreen`, listing a role's courses.
- Entry point: a "Browse departments & roles" button inside the existing
  Tech Center section of the "Sections in depth" tab
  (`skill_up_screen.dart`).

Neither new route was added to `RoutePaths.publicRoutes`/`universalRoutes`/
`employerProtectedRoutes` — both inherit the same default-protected,
login-required behavior every other Skill Up route already has.

## Manifest format and entry count

`lib/features/skill_up/data/tech_center_catalog.g.dart` — a generated,
`const kTechCenterDepartments = <TechCenterDepartment>[...]` list:
**10 departments, 93 roles, 383 courses**. Generated by `tool/
generate_tech_center_catalog.dart`, a new Dart script (kept in the repo,
not shipped in the app) that:
1. Takes the Django reference's path as a required CLI argument (never
   hardcoded) — `dart run tool/generate_tech_center_catalog.dart
   <path-to-royalStaffing_CB01>`.
2. Parses `static/001 Career Buddy/index.html`'s `#depth-tech` article with
   the `html` package's real DOM parser.
3. Cross-validates every parsed path against the real on-disk files, in
   both directions, and checks for duplicate `relativePath` values.
4. Prints its own validation result (acts as this phase's reproducible
   audit script) and writes the generated Dart file only after parsing
   succeeds.

## How each lesson is mapped to the source

Each `TechCenterCourse` carries the real `title=` query-param text (URL
-decoded) and the real `relativePath` from the course's own
`#load=<relativePath>&title=<title>` link inside its role's card. Each
`TechCenterRole` carries its real `<h4>` title and `<span class="chip">`
category. Each `TechCenterDepartment` carries its real `<h3>` title. No
field was derived from the filesystem path or invented — everything comes
from the real page's own markup, one property per real HTML attribute/text
node.

One real layout bug was found and fixed during this phase's own testing
(not a pre-existing regression): `TechCenterRolesScreen`'s role-category
text ("Product and Engineering"/"Business and Support" — both notably
longer than the Non-IT screen's own short "N skills" text it was modeled
on) could overflow horizontally on a narrow screen when combined with the
course-count badge in the same row. Fixed by wrapping the category text in
`Flexible` with ellipsis overflow, and the role title in a 2-line ellipsis,
before this code was ever committed — confirmed via the "renders without
overflow at narrow phone width"-style verification this phase's own tests
exercise at a 400px-wide surface.
