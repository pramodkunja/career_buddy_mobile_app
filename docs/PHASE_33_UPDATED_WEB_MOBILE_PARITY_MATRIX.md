## Notes on scope and exclusions

- Rows 9–15 (Manual Resume Builder) draw on exhaustive, already-independently-verified work from this same session (Phases 24–32) — not re-litigated from scratch, but row 11 (completeness) and row 15 (lifecycle safety) reflect genuinely new findings surfaced specifically by this phase's own fresh inspection, not merely restated from an earlier report.
- Row 20 is flagged **Blocked / needs re-check** rather than asserted as broken or fixed, because this phase did not have time to independently re-trace the current MCQ/Matching submission payload against the current backend contract — given Phase 15 called it the single most severe finding of its entire audit, confirming its current status is treated as a P0 item in the main report's action plan, not assumed resolved.
- Marketing-only landing-page sections (row 5) are explicitly *not* treated as required parity — the underlying features they market all exist elsewhere in the app; this is a presentation-completeness question, not a functional one.
